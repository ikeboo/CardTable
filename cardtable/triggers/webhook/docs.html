Pythonから送信する

画像をBase64に変換して、任意の名前で指定します。requests を利用する例です。

import base64
from pathlib import Path
import requests

def image(path, content_type):
    path = Path(path)
    return {
        "filename": path.name,
        "content_type": content_type,
        "content_base64": base64.b64encode(path.read_bytes()).decode("ascii"),
    }

response = requests.post(
    $endpoint_literal,
    ${auth_python}json={
        "texts": {
            "instruction": "2枚の画像を比較してください",
            "language": "日本語",
        },
        "images": {
            "before": image("before.jpg", "image/jpeg"),
            "after": image("after.png", "image/png"),
        },
    },
    timeout=$client_timeout,
)
body = response.json()
response.raise_for_status()
if body["status"] == "succeeded":
    print(body["result"]["texts"])
    for name, result_image in body["result"]["images"].items():
        result_bytes = base64.b64decode(result_image["content_base64"])
        print(name, len(result_bytes))
else:
    print("結果は後で取得できます:", response.headers["Location"])

JSONのデータ形式

本文はUTF-8の application/json です。texts と images の片方は省略できます。少なくとも1項目を指定してください。

項目型・ルール
texts名前と文字列のオブジェクト。名前は空文字不可。値は空文字も可能。
images名前と画像オブジェクトの対応。名前は空文字不可。
images.*.filename空でないファイル名。メタデータとして扱い、保存先には使用しません。
images.*.content_typeimage/jpeg、image/png などの image/*。
images.*.content_base64空でない画像バイト列のBase64文字列。改行・空白・data URLの接頭辞は付けません。

定義されていない項目とJSONの重複キーはエラーになります。テキストと画像で同じ名前を使うことは可能です。

$example

サイズと件数

  • リクエスト本文全体：最大 $max_body_bytes バイト。JSONとBase64の付加分を含みます。
  • テキストと画像の合計：最大 $max_items 項目。
  • 本文読み取りの無通信タイムアウト：$request_timeout 秒。
  • POSTで結果を待つ時間：最大 $response_timeout 秒。待機時間にはキュー待ちも含みます。
  • 結果の result オブジェクト：最大 $max_result_bytes バイト（JSON・Base64込み）。
  • 圧縮本文には対応しません。本文サイズはchunked送信でも制限します。

画像はBase64を検証してバイト列に戻します。画像としてのデコード・形式の検証・ファイル保存は行いません。

推論結果のレスポンス

HTTP/1.1 201 Created
Location: $path/0123456789abcdef0123456789abcdef

{
  "event_id": "0123456789abcdef0123456789abcdef",
  "text_count": 2,
  "image_count": 2,
  "status": "succeeded",
  "result": {"texts": {"answer": "推論結果です"}, "images": {}},
  "error": null
}

結果は status で判断します。 既定のPOSTは完了時に201と結果を返します。待機上限を超えると202と pending を返し、推論は継続します。?wait=false は201と pending を返します。

result.texts は名前付きの文字列、result.images は入力画像と同じ filename・content_type・content_base64 です。

Location のURLへGETすると状態と結果を取得できます。認証設定時はGETにも同じBearerトークンを付けてください。GETは取得成功なら200で、推論失敗時も状態をJSONで返します。

status意味
pendingキュー待ち、または推論中。resultはnull。
succeeded完了。resultからテキスト・画像を取得できます。
failed推論例外、戻り値の不正、または結果サイズ超過。errorを確認してください。
cancelled結果取得前に受信口が停止しました。実行中の推論処理の強制終了を意味しません。

履歴は最大 $history_size 件 の結果をメモリに保持します。入力本文は履歴に残しません。未完了イベントは削除せず、枠がすべて未完了なら新規受付を503で拒否します。枠が必要になると古い完了結果から削除します。画像結果が大きい場合は保持件数を小さく設定してください。

履歴から削除されたIDと、受信口の停止・再起動前のIDは404になります。自動再送・重複排除は行いません。同じ内容を再送すると別の推論になります。クライアントの切断や待機タイムアウトだけでは、受付済みの推論は取り消されません。

エラー

{"error":{"code":"invalid_payload","message":"Body must be a UTF-8 JSON object"}}
HTTP原因
400JSON・項目・Base64が不正、重複キー、本文不足、対応外の転送方式
401トークンが未指定または不一致
404URLやIDが不明、または受付履歴の保持対象外
405HTTPメソッドが不正。Allow ヘッダーを確認してください。
408リクエスト本文の読み取りがタイムアウト
413本文サイズまたは項目数の上限超過
415Content-Type・文字コード・圧縮方式が未対応、または画像の宣言が image/* でない
503待ち行列・未完了履歴の枠が満杯、処理中の受付を抑止、または停止中。停止時に待機中だった応答はcancelledを返します。
500待機中の推論が失敗した場合はevent_id・status・errorを返します。予期しないサーバーエラーも500です。

入力検証が失敗した場合は、一部だけを受け付けることはありません。
